TriZetto direct

Reads the payers' remittances straight from TriZetto every hour, with a login of RemitWatch's own, so nobody has to copy files into Dropbox and paid claims leave the lists within hours. Read only: nothing on TriZetto's server is moved or deleted.
  1. Send TriZetto the written request in docs/TRIZETTO_REQUEST.md, through the portal's Contact Us. No phone call. It asks for a second SFTP login for RemitWatch.
  2. Change nothing in TriZetto's portal for this. Leave the Remittance Advice Settings (Auto Generate Remittances) as they are. Never reset the Site ID's SFTP password: ModMed may sign in with it.
  3. When TriZetto answers in writing, enter the new login on the server with configure.sh, TriZetto section: TRIZETTO_SFTP_USER (the login TriZetto issued for RemitWatch, not the Site ID), TRIZETTO_SFTP_PASSWORD (given by phone or in person, never by email), how many days it lasts, TRIZETTO_SFTP_DIRS (the folder TriZetto named) and TRIZETTO_SFTP_HOSTKEY (every fingerprint TriZetto gave). TRIZETTO_SFTP_HOST only if TriZetto names a server other than sftp.gatewayedi.com.
  4. Press the button below. If TriZetto refuses the sign-in, nothing signs in with that password again for a day. Ask TriZetto in writing to reset the RemitWatch login's password. Change it yourself only on a page that shows the RemitWatch login's username.
The server reads TriZetto. A site on Vercel does not, unless TRIZETTO_SFTP_SERVERLESS=1 is set there, and then no server may read it with the same login.

Fax line

Faxes each appeal to the payer, reads what payers fax back, and follows up every week until each claim is paid or decided. The service is SRFax: pick a plan for healthcare, sign its business associate agreement, then set these in the host's settings (on the server, with configure.sh; on Vercel, then redeploy).
  1. SRFAX_ACCESS_ID (the account number) and SRFAX_ACCESS_PWD (the account password).
  2. SRFAX_CALLER_ID: the fax number SRFax gives the account. Letters give it as the practice's fax, so payers answer to it and their answers are read here.
  3. SRFAX_SENDER_EMAIL: where SRFax sends its own delivery notices.
Only one site sends faxes, so no fax goes out twice. REMITWATCH_FAX_SENDER names it: server (the practice's server, the default) or serverless (the Vercel site; set it there when no server runs). none pauses faxing. The other site shows the Faxes page and opens the faxes that came in, and sends nothing.

ModMed EMA connection (optional)

Optional. Visit notes come in by hand: export the note from EMA as a PDF and upload it on Upload from EMA or in the item's appeal step. Connect EMA here only if the practice decides to use ModMed's API (read only: nothing is written to EMA).
Set up the ModMed connection
  1. Make the app's key: python -m remitwatch.cli modmed-key. Put the private key in the host's settings as MODMED_PRIVATE_KEY (on the server, with configure.sh; on Vercel, then redeploy).
  2. Register the app with ModMed (portal.api.modmed.com) as a Bulk FHIR backend app. Give it the public key printed with the private one, or this address:
  3. In EMA: Admin, Manage Bulk FHIR, add the app's client ID. Then set MODMED_CLIENT_ID the same way.
