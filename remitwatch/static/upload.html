The weekly routine

Every Monday (one named person, with a backup), pull the five exports in the checklist above and drop them here, or put them in the Dropbox folder. The A/R report and the Production report come with every column and no filter but the date. The three weekly exports (Encounter & Charge Lines in its full layout, ERA & Payment Line Adjustments, and Claim & Claim Status with the Patient ID column) are pulled by posting or transaction date for the last five weeks where EMA allows it, else for the last six weeks by date of service. Encounter & Charge Lines must carry Patient ID, Bill Creation Date, Claim ID and Insurance Payments: Insurance Payments is what lets RemitWatch close an item EMA shows as paid. Why the weeks overlap: a visit shows up only once its bill exists, so a week pulled the day it ends misses every visit billed later. Repeating the weeks catches them, and RemitWatch keeps each row once, so the overlap never counts twice. Write the practice's own steps in each row's "How we pull this in our EMA" box: RemitWatch never guesses EMA's menus.

If ModMed offers an API

Ask for: each payment and adjustment posting by line, with the check or EFT number, the posted date and the reason code; A/R balances by line; claim status with its dates; and charges with the claim ID and modifiers. Ask too whether EMA can send these reports on a schedule to a secure place (SFTP or a shared folder), not by email.

When remittances stop coming

The Data tab says when the newest remittance is days old. Ask TriZetto in writing (the portal's Contact Us) to re-send the missing ERA (835) files to the RemitWatch login (docs/TRIZETTO_REQUEST.md, point 4). Do not download them in the portal yourself, not even archived ones: that can send them to ModMed again. ERA files you already have can be dropped here (a .zip of them is fine). A remittance RemitWatch has already is recognised by its content and not counted twice.

Visit notes, as items need them

For each row under "Visit notes appeals are waiting for": in EMA open the patient's visit on that date of service, and print or save the signed note as a PDF (one PDF per visit). Drop the PDFs here together; each is matched by the patient's name and the date of service it states, and the summary says which visit it went to. A note that states the patient's EMA Patient ID (or record number) goes into the appeal by itself. One that matches only by name and date waits for a person: two patients can share a name and a visit day, so open the item and confirm the note there, or attach it with the row's Attach note button. A scanned page (a picture, no text) cannot be read either way: attach it with the row's Attach note button. When a note fits more than one visit, pick the right one under Other files uploaded. Then the item's appeal goes as it would with a note from EMA: open it, or use Appeal everything appealable. Visit notes are uploaded on the practice's own server.

What happens to the files

Before a file is sent, this page works out its checksum (SHA-256). Large files go in pieces of 4 MB, each checked as it arrives, and the whole file is checked against that checksum at the end: a file that does not arrive whole is not kept, nor one no export EMA makes looks like (one that unpacks to hundreds of times its size, or has a line longer than a megabyte). On the practice's server each file is kept in the same protected place as RemitWatch's store; on the Vercel site, reports and exports go to the private Dropbox folder RemitWatch keeps its data in. The files themselves are never emailed. Exports and remittance files never leave RemitWatch's storage. A visit note leaves it only inside the appeal packet built from it: faxed to the payer, or emailed where the practice has allowed that. When the note review is switched on, the note is also read by that review. Reports and exports are read by the next cycle; what each held, and what it replaced, then shows here. Uploading the same file again changes nothing: RemitWatch knows a file by its checksum, the same way whether it was uploaded or found in the Dropbox folder.
