Getting each file out of EMA

Run these from EMA's reports as the practice already does for the Dropbox folder: the same three reports, saved and dropped here instead. Excel (.xlsx) is best; CSV works too. Pick the date range by date of service.

Every week (say Monday): three reports, the last six weeks by date of service

  1. Encounter & Charge Lines, in its full layout. It must carry these columns: Service Date, Patient ID, Bill ID, Bill Creation Date, Claim ID, Bill Item Identifier, CPT/Product, Modifiers, Units, Charges, Insurance Payments, Activity Type, Primary Provider, Payer and Location. Insurance Payments is what lets RemitWatch close an item EMA shows as paid; Patient ID ties a visit billed to two payers to one patient and finds its note.
  2. ERA & Payment Line Adjustments (the ERA & Payment Lines report): Claim ID, CPT, Service Date, Reason Code, RARC Code, Adjustment Status and Subtype, Adjustments, Payments and Transaction Date. It says what the biller did with each adjustment (written off, moved to the patient).
  3. Claim & Claim Status, with the Patient ID column added: Claim ID, Claim Status, Denial Amount, Denial Category and the reason codes. A claim EMA shows as rejected or still waiting has no remittance, so without Patient ID nothing says whose it is.
Why six weeks: a visit shows up in a report only once its bill exists, so a week pulled the day it ends misses every visit billed later. Repeating six weeks each time catches them; RemitWatch keeps each row once, so the overlap never counts twice. After each upload the summary says what was new, what it had already, and what it left out (the report's title lines, a totals line) and why. If a column it uses is missing, the summary names it.

When remittances stop coming

The Data tab says when the newest remittance is days old. Ask TriZetto in writing (the portal's Contact Us) to re-send the missing ERA (835) files to the RemitWatch login (docs/TRIZETTO_REQUEST.md, point 4). Do not download them in the portal yourself, not even archived ones: that can send them to ModMed again. ERA files you already have can be dropped here (a .zip of them is fine). A remittance RemitWatch has already is recognised by its content and not counted twice.

Visit notes, as items need them

For each row under "Visit notes appeals are waiting for": in EMA open the patient's visit on that date of service, and print or save the signed note as a PDF (one PDF per visit). Drop the PDFs here together; each is matched by the patient's name and the date of service it states, and the summary says which visit it went to. A note that states the patient's EMA Patient ID (or record number) goes into the appeal by itself. One that matches only by name and date waits for a person: two patients can share a name and a visit day, so open the item and confirm the note there, or attach it with the row's Attach note button. A scanned page (a picture, no text) cannot be read either way: attach it with the row's Attach note button. When a note fits more than one visit, pick the right one under Uploaded. Then the item's appeal goes as it would with a note from EMA: open it, or use Appeal everything appealable.

What happens to the files

Each file is kept on the practice's server, in the same protected place as RemitWatch's store. The files themselves are never emailed. Exports and remittance files never leave the server. A visit note leaves it only inside the appeal packet built from it: faxed to the payer, or emailed where the practice has allowed that. When the note review is switched on, the note is also read by that review. Exports and remittance files are read by the next cycle, which starts within about a minute; the worklist updates when its analysis finishes (a few minutes). Uploading the same file again changes nothing.
