# Brief: send each item the easiest way the payer accepts (unit `routes`, started 2026-11-28)

Read with `plans/briefs/2026-11-26_common.md`, CLAUDE.md and plans/HANDOFF.md. Base: the integration tip
(`origin/claude/ecstatic-fermi-orfcgo`, dd94414 or newer). This unit needs no real data: invented data only.

## The owner's ask

"Confirmed which payers require or take fax and which require portal, so we route the first time by the easiest route.
Least work for billers, autofill any fields needed, auto copy what's needed."

## The research (done, public sources only)

`$S/tk/routes/research_raw.json` (outside the repository; copy what you need, never the file itself) holds the result of a
research workflow: four payer clusters (`medicare`, `anthem_humana`, `uhc_optum`, `other_commercial_medicaid`), 191 rows
of payer group x request type, 25 payer groups. Each cluster has:
- `found.payers[]`: `payer_group`, `plan_scope`, `request` (one of `medicare_reopening`, `medicare_redetermination`,
  `reconsideration_or_first_appeal`, `second_level_appeal`, `corrected_claim`, `records_or_attachments`,
  `overpayment_refund`, `claim_status_or_reprocess`, `timely_filing_proof`), `time_limit`, `confidence`, and `channels[]`
  ranked easiest first (`rank`, `channel`: payer_portal, clearinghouse, phone, fax, mail, email, not_accepted; `name`,
  `where` (URL, phone, fax number or address), `form`, `fields[]`, `attachments[]`, `minutes`, `notes`, `source_ids`).
- `found.sources[]` (id, url, title, publisher, date, quote) and `found.gaps[]`.
- `verdict.checks[]`: an independent verifier's verdict on single facts (`verified`, `contradicted`, `unverified`, with
  the evidence quote and URL) and `verdict.missing[]` (facts it found that the table lacks, with sources).
Use the verifier's corrections: a contradicted fact is fixed from its evidence or dropped; an unverified one is kept and
marked unverified. Take the useful `missing` facts that carry a source (for example: Kentucky and Indiana VA Community
Care claims belong to CCN Region 2, which Optum administers; Cigna Medicare Advantage is now HealthSpring).

## What to build

R1. `remitwatch/payer_routes.json` (or a Python data module): for each payer group and request type, the ranked channels
with the fields above, `verified` per channel, the sources (url, title, publisher, date), the time limit text, and the
day the table was checked (2026-11-28). Public payer facts only. No practice identifier of any kind (NPI, tax ID, PTAN,
TriZetto Site ID, practice name or address), no patient data, no live site address. Phone and fax numbers written as
`866-290-4036`; run `tests/test_docs.py` with `REMITWATCH_PRIVATE_WORDS=$S/docs_private/all_words.txt` (never print that
list) and make sure no number in the file trips the tax ID or NPI shapes.

R2. `remitwatch/routes.py`: the one place that picks an item's route.
- Request type from the item's route (`states.route_of`: appeal, corrected, call, refund, eob_first, cob, rate,
  repricing...), its signal and facts, and the payer: Original Medicare appeal is a redetermination, or a reopening when
  the fix is clerical (a code, modifier, units or date correction the payer allows by reopening); a second appeal after a
  recorded first denial is `second_level_appeal`; `call` is `claim_status_or_reprocess` (and `timely_filing_proof` when
  the first-filing limit is near); `corrected` is `corrected_claim`; `refund` is `overpayment_refund`. Routes with no payer
  step (post, bill_patient, contract, policy, fees, decide, wait, nothing) get no card.
- The payer group from the item (the app's payer groups in `codes.py`) mapped to the research's groups, with plan scope
  (Original Medicare vs Medicare Advantage, commercial vs Medicaid) taken into account; no match gives a plain fallback
  ("No checked route for this payer yet. Use its provider portal, then note what worked.").
- The channels in rank order, `not_accepted` ones kept as warnings ("CGS does not take reopenings by fax").
- Prefilled fields: each field the channel names, filled from the item and its claim where the store holds it (patient
  name only when the names switch is on, member id, date of service, codes and modifiers, billed and paid amounts, payer
  claim number or ICN, denial reason codes, the deadline) and from the practice's settings for practice fields (read
  existing settings first: fax and appeal letters already use some; add any new ones to `.env.example` and the runbooks
  by name, never a value). A field with no value is shown empty with what to fill, never invented.
- A fax channel never sends to a number a person has not confirmed: the card shows the published number with "confirm
  it before the first fax" and uses the app's existing fax-number confirmation, never a new path around it.

R3. The API: the item payload (or one new route under the existing item API, with the same auth) carries the route card
data, on both hosts (the server's store and Vercel's dashboard copy: check that the fields it reads are in the serving
tables, or add them and bump the serving build as the code does).

R4. The drawer card, at the top of the next step: the easiest accepted route as one line ("Availity: claim payment
dispute, about 6 minutes") with its main button (open the portal, start the fax, print the mail form), the deadline, then
the prefilled fields each with a copy button, one "Copy all" that copies a clean block, the attachments the route needs
with links to what the app already builds (appeal letter, packet, remittance page), the other accepted routes folded,
the not-accepted warnings, and the source line ("From CGS, myCGS Reopenings, checked 2026-11-28"). "I sent it" records
the existing action with the channel and an optional reference number (portal submission id). Keyboard: one key copies
all. Keep the markup semantic and use the classes the drawer uses now: a design pass on every page follows this unit.

## Tests and checks

Invented data only. Route choice per signal and payer group (including unknown payer, Medicare reopening vs
redetermination, MA vs Original, second level, names switch off: no name in any field or in "Copy all"), the fax rule,
the data file's integrity (every channel has a source; ranks unique; no contradicted fact left; every request type
known), the API on both hosts, a Playwright check of the card at 1400 and 390 px, test_docs with the private words, the
four environments, and the two node checks. README's module list names the new module (tests/test_docs.py checks).
