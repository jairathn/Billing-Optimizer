# RemitWatch

RemitWatch reads the practice's own payer remittances (X12 835 files from TriZetto) and ModMed EMA exports, links what was paid to what was billed, and shows exactly where money is being lost: downcoding, bundled-away visits, silent line denials inside "paid" claims, whole-claim denials that were never worked, allowed amounts below the payer's own rate or below Medicare, multiple-procedure reductions beyond policy, payment fees skimmed through PLB segments, and takebacks. Every finding carries the evidence, an estimated appeal deadline and a ready-to-send letter or correction instruction.

It runs hands-off: a weekly job pulls new files from the `Trizetto Data` Dropbox folder, ingests them, re-runs detection and emails a summary. Nothing is sent to an outside service; the appeal letters are templates filled from the data.

Built for Owensboro Dermatology Associates. Everything is practice-agnostic except `PRACTICE` in `remitwatch/appeals.py` and the payer name rules in `remitwatch/codes.py`.

## What it found (the archive through September 2026)

See `docs/DATA_FINDINGS.md` (regenerated by `scripts/leak_report.py`). Headline: about $3.25M of detectable leakage over 2024 to 2026, of which classic E/M downcoding is only about $80K. The large items are unworked denials ($1.16M), the Anthem commercial contract paying office visits at 59 to 72 percent of Medicare ($616K at Medicare parity), bundled-away E/M visits and Mohs stages ($430K), Medicare Advantage rates below Medicare ($261K), takebacks ($460K) and payment fees ($67K). The MIPS bonus fell from about $308K in 2024 to $14K in 2026.

## Signals

| category | signal | meaning | action |
|---|---|---|---|
| downcoding | DOWNCODE_SVC06 | payer reported the billed code (SVC06) and paid a lower level | appeal |
| downcoding | DOWNCODE_CHARGE | charge equals the practice's fee for a higher level than the paid code | appeal |
| downcoding | DOWNCODE_RATE | allowed equals the payer's usual rate for a lower level | appeal |
| downcoding | DOWNCODE_LEVEL_DENIED | CARC 150/186 or RARC M25: level not supported | appeal |
| downcoding | CODE_CHANGED | payer changed the code outside the level families | review |
| bundling | EM_BUNDLED_MOD25 / MOD24 / MOD57_MAJOR | E/M paid $0 as included in a procedure | appeal |
| bundling | EM_BUNDLED_NO_MODIFIER / MOD57_MINOR | E/M bundled because the modifier was missing or wrong | correct and resubmit |
| bundling | ADDON_BUNDLED, PROCEDURE_BUNDLED | add-on or procedure bundled into another service | appeal |
| denial | DENIED_MISSING_MODIFIER, DENIED_CODING, DENIED_MISSING_INFO | correctable errors (CO-16/4 with RARC) | correct and resubmit |
| denial | DENIED_AUTH, DENIED_MEDICAL_NECESSITY, DENIED_FREQUENCY | payer judgment calls | appeal with records |
| denial | DENIED_TIMELY_FILING, DENIED_PROVIDER, DENIED_NONCOVERED, DENIED_DUPLICATE_UNPAID, DENIED_OTHER | process failures | review |
| denial | CLAIM_DENIED_UNPAID | whole claim denied and never paid later | appeal or resubmit |
| underpayment | UNDERPAID_VS_OWN_RATE | allowed below the payer's usual rate, no reason reported | appeal |
| underpayment | MPPR_EXCESS | multiple-procedure reduction beyond policy or on an add-on | appeal |
| fees | FEE_SKIM | Zelis transaction fees, origination fees withheld (PLB CS/AH) | opt out |
| fees | TAKEBACK | overpayment recovery withheld (PLB WO) | review |
| contract | CONTRACT_RATE_GAP | commercial rate far below Medicare on a high-volume code | renegotiate |
| contract | MA_BELOW_MEDICARE | Medicare Advantage rate below Medicare | review contract |
| info | G2211_DENIED, MIPS_ADJUSTMENT, SEQUESTRATION | context | none |

## Quick start (local)

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

```bash
# 1. parse remittances and EMA exports into the store (idempotent; re-run any time)
python -m remitwatch.cli --db data/remitwatch.sqlite ingest-835 "data/dropbox/Trizetto Data"
python -m remitwatch.cli --db data/remitwatch.sqlite ingest-ema "data/dropbox/Trizetto Data"
# 2. run detection
python -m remitwatch.cli --db data/remitwatch.sqlite detect
# 3. dashboard on http://127.0.0.1:8000
REMITWATCH_PASSWORD=change-me python -m remitwatch.cli --db data/remitwatch.sqlite serve
```

## Hands-off weekly run

```bash
python -m remitwatch.cli oauth      # once: prints the Dropbox refresh token for .env
python -m remitwatch.cli weekly     # sync Dropbox -> ingest -> detect -> report (-> email)
```

Schedule `weekly` with cron (`deploy/crontab.example`), with `docker compose up -d` (the container runs the dashboard and a Sunday 03:00 UTC job), or with any scheduler that can run a container. Setup and hosting notes: `docs/OPERATIONS.md`.

## Layout

```
remitwatch/
  x12_835.py      835 parser (all loops, balancing, content fingerprint for duplicate detection)
  x12_837.py      837P reader (what was submitted)
  ema_exports.py  ModMed EMA xlsx loaders (charge lines, ERA lines, claim status)
  store.py        SQLite store, idempotent ingestion
  fees.py         fee-schedule inference from charges; payer rate tables
  codes.py        CARC/RARC texts, global periods, add-on codes, payer normalization
  detect.py       detection engine -> findings table
  appeals.py      appeal letters and correction instructions
  dropbox_sync.py Dropbox API client (refresh token, cursor deltas, downloads)
  report.py       weekly Markdown report and email
  api.py          FastAPI endpoints
  static/         dashboard (single page, no build step)
  cli.py          ingest-835 | ingest-ema | detect | serve | oauth | sync | weekly | stats
docs/             findings, architecture, operations, missing data, research
deploy/           container entrypoint, cron example
tests/            synthetic-fixture tests (no PHI)
```

## PHI

The store and the Dropbox mirror contain patient names, member IDs and dates of service. `data/` is git-ignored. Run the dashboard behind HTTPS with the shared login, keep the host under a BAA, and leave `REMITWATCH_SHOW_PHI` off unless the viewer needs names.
